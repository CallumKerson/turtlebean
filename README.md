# turtlebean

A clean-room parser and lossless writer for
[beancount](https://beancount.github.io/docs/) ledgers, in Rust.

turtlebean is at an early stage and has no public API yet.

## Goals

- **Parse a well-defined subset of beancount v3**, and reject anything outside
  it with a clear error rather than guessing.
- **Write losslessly.** Editing a ledger keeps comments, ordering and
  alignment, so changes show up as small git diffs.
- **Match Python beancount** on everything in the subset: the same balances
  and the same errors.
- **Stay permissively licensed** (MIT), so any project can use it.

## Supported subset

The first target is the subset a real personal ledger uses:

- Directives: transactions (`*`, `!`, `txn`), `open`, `close`, `balance`,
  `pad`, `price`, `commodity`, `custom`, `option` and `include`.
- Tags, links and metadata on directives and postings.
- Postings with `{cost}` lots and `@` / `@@` prices, plus arithmetic in
  amounts.
- Semantics: filling in an elided posting, tolerance inference, `balance` and
  `pad` checks, and booking for cost lots.

The query language and other booking methods are out of scope for now.

## Plugins

Plugins change or check a ledger's entries while it loads, after booking and
before the `balance` checks and validation, where Python beancount runs its
own. A plugin is any function with this shape:

```rust
fn plugin(entries: &mut Vec<turtlebean::Entry>, ctx: &mut turtlebean::PluginContext<'_>)
```

- `load_file` runs the built-in plugins a ledger declares with
  `plugin "name"`, under beancount's module names.
- `Loader` chooses the plugins: `.plugin(name, f)` runs `f` when a ledger
  declares `name`, with the directive's configuration; `.always(name, f)` runs
  `f` on every ledger.
- A declared plugin that isn't registered is reported as an `Unsupported`
  error, as its changes are missing.
- Entries made while loading, such as padding, have `Origin::Generated`.
  Never write them back to a file.

There are no built-in plugins yet. Each will match Python beancount's
observed behaviour.

## Testing

turtlebean's results are compared with Python beancount (`bean-check` and
`bean-query`), run as a separate program. Beyond hand-written tests, it will
be checked against ledgers generated by `bean-example` and against public
compatibility corpora. Those corpora are downloaded at test time and never
committed, as their files carry mixed licences.

## Clean-room implementation

turtlebean is written from the beancount documentation and published
specifications. It doesn't contain, port or derive from code in Python
beancount (GPL-2.0) or rustledger (GPL-3.0). Contributions must follow the
same rule.

## Development

```sh
mise install        # toolchain and linters
mise run setup      # git hooks
mise run test       # cargo nextest
mise run check-all  # clippy, rustfmt, cargo-deny and the other linters
```
